# NonFinite 当前复刻口径纠正与试玩反馈复核

日期：2026-09-06

## 结论

试玩反馈成立：此前本地工作区的画面不能称为 70%、90% 或 95% 的游戏内复刻。
尤其是“大蓝星”和石块背景的扰动，不是当前游戏题目的真实运行时结果。

本次复核确认，问题不是“再调几个正弦参数”就能解决，而是把三类不同证据混在了同一条默认渲染路径：

1. 真实客户端 DXBC 字节码；
2. 测试用/占位的 `ps_const[130..139]`；
3. 从录屏拟合出的目标位置、透明度和参考背景。

只有第 1 类能证明 Shader 程序存在，不能单独证明第 2、3 类与某一道线上题目一致。

本轮只读检查了当前安装文件：

  `LieDetector`、`LieDetectorMat`；
- `LieDetectorMat` 的静态属性仍是 `_Resolution=(750,500)`、`_MainTex` 石块纹理，
  `_BackTex/_PathTex` 为空；
- Shader 的 `ps_const` 是编译后常量缓冲布局中的 10 个 Vector4，落在 `cb0[130..139]`。

这些证据支持“游戏有运行时参数驱动的程序化 Shader”，不支持“当前离线窗口已经复现某道题”。

## 为什么旧试玩会出现大蓝星

旧工作区在本地发现 DXBC 文件时自动启动离屏渲染器。测试数据使用的是人为构造的
`TEST_PS_CONST`，不是从游戏某道题记录出来的运行时常量；因此 DXBC 根据这些值选择了
一个明显的几何分支，输出大而偏蓝的图形。

同时，旧软件回退路径还对录屏提取的石块参考帧套了一层 Pillow `sin/cos` mesh 变形。
这套公式没有来自当前 Shader、Prefab、Material 或题目参数，不能叫原版扰动。

## 已修正

- 默认路径不再因为存在 DXBC 就自动启动 harness；
- 默认路径不再对石块参考帧应用手写正弦/mesh 变形；
- 录屏拟合目标改为显式 `--observed-figure` 才显示，默认不冒充运行时目标；
- 旧测试改为验证“无真实运行时参数时画面保持静态”，并增加观察回放的显式 opt-in 测试；
- Unity 对象图读取器修复了空 PPtr 的异常处理，避免根节点几何核验被无关空引用中止；
- 当前工作区 NonFinite 视觉测试：24 项通过。

## 当前能诚实交付的内容

- 原始资源、Prefab/Material/Shader 的离线核对；
- 真实 DXBC 的离屏执行 harness，但必须由用户明确提供离线运行时常量；
- 录屏参考帧回放；
- F0/F8 数据记录、导出和回归测试接口。
