# Cron 时区换算规则

## 问题
设 cron 时，Hermes Agent 使用 **UTC 时间**，但用户大概率在非 UTC 时区。如果直接写"凌晨3点"而不转换，会差几个小时。

## 大佬所在时区
- Asia/Hong_Kong = GMT+8
- 大佬常用时间：凌晨 00:00 - 03:00

## 换算公式

```
用户当地时间 → UTC = 用户时间 - 8小时
UTC → 用户当地时间 = UTC时间 + 8小时
```

### 常用对照表（大佬 GMT+8 视角）

| 用户当地时间 | UTC 时间 |
|------------|---------|
| 凌晨 00:00 | 前一天 16:00 |
| 凌晨 03:00 | 前一天 19:00 |
| 上午 11:00 | 凌晨 03:00 |

## 验证命令

```bash
# 查看当前 UTC 时间和用户时间
date
TZ='Asia/Hong_Kong' date

# cron 表达式：每天凌晨3点（大佬时间）
0 19 * * *   # = UTC 19:00 = HKT 次日 03:00
```

## 实际教训（2026-04-23）

设研究员 cron 时，我误把 UTC 03:00 当作"大佬凌晨3点"。
- 实际情况：UTC 03:00 = HKT 11:00（上午，不是凌晨）
- 正确做法：HKT 凌晨 3:00 = UTC 前一天 19:00
- 教训：每次设 cron 前必须 `TZ='Asia/Hong_Kong' date` 确认当前时间，再换算

## 每次设 cron 前必做
1. 确认当前 UTC 时间和用户时间
2. 计算差值（UTC = 用户时间 - 8）
3. 写 cron 表达式前再换算回去验证
4. 设完记录到 cron job 的 name 或 prompt 里

## 坑
- 如果用户说"今天凌晨3点"，指的是**下一个**凌晨3点（已过的那个不算）
- Cron 是固定周期，不区分工作日/周末，需注意
